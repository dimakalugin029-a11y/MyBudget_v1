# Устойчивое хранение фото ЖКХ

## Найденная проблема
Раньше, если папка ЖКХ не была выбрана или копирование в неё не удавалось, persistPhoto сохранял исходный URI из Photo Picker. Ошибка takePersistableUriPermission игнорировалась, после чего запись всё равно добавлялась в базу. Копия в выбранной папке также зависела от доступа к внешнему хранилищу. Это подтверждённый дефект хранения; точная причина уведомления на конкретном телефоне без повторного экспорта с диагностикой не установлена.

## Изменения
- Сначала создаётся независимая копия внутри filesDir/restored_photos; URI прежнего FileProvider совместим с полными архивами.
- Если файл не читается, пуст или больше 32 МБ, запись с временным URI не создаётся, пользователь получает сообщение о несохранённых фото.
- Выбранная папка остаётся местом дополнительных копий. Её недоступность не мешает сохранению основного вложения. Удаление вложения из приложения удаляет его внутреннюю копию; дополнительные копии остаются в выбранной папке.
- Импорт архива тоже сохраняет основное вложение внутри приложения.
- При открытии списка фото доступные старые внешние вложения копируются внутрь приложения. Ссылка меняется условным UPDATE по id и прежнему URI; остальные поля и оригинал не меняются. Если другая операция уже изменила запись, новая невостребованная копия удаляется.
- Старое поле receiptPhotoUri при открытии экрана переносится в обычные вложения в транзакции. Это делает старую ссылку видимой для исправления/удаления и предотвращает её повторное появление после удаления последней квитанции.
- Ошибка экспорта содержит объект, месяц, тип и номер фото и различает отсутствие доступа, отсутствующий/пустой файл и превышение ограничения. Номер виден на миниатюре. Неисправное вложение не пропускается молча, неполная копия не объявляется успешной.

Уже утраченный файл не восстанавливается из URI. Для него нужно вернуть доступ к прежней папке или удалить недоступное вложение и добавить исходное фото заново. Схема базы и формат архива не менялись.

## Проверка на устройстве
1. Открыть фото старых месяцев, повторить ручной полный экспорт. Если ошибка осталась — проверить указанные объект, месяц и фото.
2. Добавить фото без выбранной папки. Удалить оригинал из галереи, перезапустить приложение и проверить просмотр/экспорт.
3. Повторить при недоступной дополнительной папке.
4. Импортировать полный архив, проверить фото и повторный экспорт.
5. Проверить автоматический экспорт после перезапуска телефона.

Добавлены тесты на независимость от исходного файла, недоступную папку, отказ сохранения недоступного источника, перенос старого вложения и отказ полного экспорта с точной диагностикой. Android-тесты требуют запуска на устройстве; их компиляция не означает выполнения.
