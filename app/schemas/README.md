# Схемы Room и проверка миграций

Текущая версия: 47. Экспорт схем включён через KSP в app/build.gradle.kts.
После изменения сущностей новую JSON-схему нужно сохранить вместе с миграцией.
Не изменяйте прежнюю схему для того, чтобы скрыть несовместимое изменение.

## Происхождение исторических схем

- 41.json: сгенерирована KSP из коммита d7c53af.
- 45.json: сгенерирована KSP из коммита e1bbff4.
- 46.json: сохранена из рабочего кода перед вводом журнала.
- 47.json: сгенерирована из текущего рабочего кода.

Для 41 и 45 исходники извлечены через git archive в изолированные папки
.temp/schema-baselines. Добавлены только exportSchema=true и путь вывода
room.schemaLocation. Kotlin-сущности и SQL миграций исторических снимков
не редактировались. Полные коммиты и SHA-256 схем — в provenance.json.
Схемы 1–40 и 42–44 этим этапом не восстановлены; их наличие не заявляется.

## Уровни проверок

1. tools/check_room_schemas.py: SQL каждой сохранённой схемы исполняется
   в пустой SQLite-базе; проверяются версия, identityHash и integrity_check.
2. tools/check_migration_sql.py: настоящий SQL из Migration41To42..Migration45To46
   исполняется на схемах 41, 45 и 46, затем вся структура сравнивается с 47.
   Для 46 → 47 проверка использует литеральный SQL общего установщика журнала.
   Сохраняются тестовые денежные строки и связи. Парсер намеренно ограничен
   простым литеральным SQL этих миграций; неизвестные выражения приводят
   к отказу проверки, а не к пропуску инструкции. Это не выполнение Kotlin-кода
   миграций и не подмена проверки Android/Room.
3. DatabaseMigrationChainTest: создаёт файловые базы из исторических схем,
   наполняет связанными тестовыми записями, открывает через актуальный Room
   с ALL_MIGRATIONS. Room валидирует всю целевую схему. Проверяются остатки,
   операции, оплаченный ремонт, плановые доходы, маркеры оплат и foreign keys.
   Тест также открывает свежую базу 47.

Android-схемы добавлены в assets тестового APK из app/schemas. Они не содержат
персональных данных. Тест создаёт базы с уникальными именами и удаляет только
эти тестовые базы, не открывает budget_database пользователя.

## GitHub

Один workflow ci.yml выполняет обе Python-проверки, модульные тесты,
компиляцию исходников Android-тестов и проверяет, что генерация Room не
изменила сохранённую схему. Отчёты прикладываются при наличии.
Сборка APK и запуск эмулятора в этот workflow не входят. Android-тесты
нужно запустить отдельно в Studio на тестовом устройстве.

Локальные задачи проверки: :app:testDebugUnitTest и
:app:compileDebugAndroidTestKotlin. Для запуска миграций в Studio выберите
DatabaseMigrationChainTest; для полноты копий — FullBackupRestoreTest.
Не путайте успешную компиляцию теста с его выполнением.

Для журнала изменений дополнительно выполняется tools/check_balance_ledger.py.
Семантика и ограничения описаны в docs/BALANCE_LEDGER.md.
